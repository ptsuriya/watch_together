# แผนหารายได้ KUMA Listening Party (ฉบับร่าง)

ร่างวันที่ 20 กันยายน 2026 · ยังไม่ได้ลงมือทำ ใช้คุยกันก่อน

> สถานะล่าสุด: เจ้าของเว็บตัดเรื่องรับบริจาคออกแล้ว และยังไม่เริ่มทำระบบสมาชิก
> โมเดลที่คุยกันไว้ล่าสุดคือ ดูฟรีเสมอ แต่สิทธิ์ให้ลูกห้อง "ส่งเข้ามา" (เพิ่มคิว ปรับคีย์ ส่งอีโมจิ ข้อความ)
> หมดเวลาหลังผ่านไปช่วงหนึ่ง แล้วโฮสต์จ่ายเพื่อต่อเวลา ดูรายละเอียดข้อ 1 และ 2

## 1. โมเดลที่ตกลงกันไว้

| ระดับ | ทำอะไรได้ |
| --- | --- |
| **ฟรี ตลอด** | เปิดห้องได้ทุกโหมด ดูวิดีโอไม่จำกัดเวลา ลูกห้องดูพร้อมกันได้ เห็นคิว เห็นเนื้อเพลง เห็นเพลงที่เล่นอยู่ |
| **ฟรี ช่วงเวลาหนึ่ง** | ลูกห้อง **ส่งเข้ามา** ได้ คือเพิ่มคิว กดเล่น/หยุด/ข้าม ปรับคีย์ ส่งอีโมจิ |
| **หมดเวลาแล้ว** | ลูกห้องยังดูต่อได้ทุกอย่าง แต่ส่งอะไรเข้ามาไม่ได้ เหลือโฮสต์คุมคนเดียว |
| **เสียเงิน (โฮสต์)** | ปลดเวลา ลูกห้องกลับมาส่งได้ตามปกติ |

หลักการ: **ไม่เก็บเงินกับการดู** เก็บกับระบบของเราเองคือการซิงก์ข้ามเครื่องและการให้มือถือคุมจอกลาง
ลูกห้องไม่ต้องสมัครและไม่ต้องจ่ายเลย จ่ายเฉพาะโฮสต์

---

## 2. กติกาเวลาและการบังคับ

**ที่ต้องตัดสินใจ** (ค่าที่เสนอไว้ในวงเล็บ)

1. นาฬิกาเริ่มนับเมื่อ **ลูกห้องคนแรกเข้าห้อง** (ไม่ใช่ตอนสร้างห้อง เพราะโฮสต์มักเปิดเตรียมไว้ก่อน)
2. ฟรีนาน **30 นาที** ต่อห้อง
3. อีโมจิ — เสนอให้ **หยุดพร้อมกัน** เพื่อให้กฎเดียวคุมทุกอย่าง ถ้าอยากให้ส่งฟรีตลอดต้องแยกช่องทางส่ง เพิ่มงานอีกนิด
4. เปิดห้องใหม่เพื่อรีเซ็ตเวลา — ช่วงแรกปล่อยให้ทำได้ (ยังไม่มีล็อกอิน) ถ้าจะปิดช่องนี้ต้องผูกโควตากับบัญชีโฮสต์
5. ข้อความตอนหมดเวลา — ลูกห้องเห็น "เวลาส่งเพลงของห้องนี้หมดแล้ว ดูต่อได้ตามปกติ" โฮสต์เห็นปุ่ม "เปิดให้เพื่อนส่งเพลงต่อ"

**บังคับที่ฐานข้อมูล ไม่ใช่ซ่อนปุ่ม**

- ตาราง `rooms` เพิ่มคอลัมน์ `guest_until timestamptz`
- ตอนสร้างห้องยังว่างไว้ ตั้งค่าเมื่อลูกห้องคนแรกเข้า เป็น `now() + 30 นาที` หรือไกล ๆ ถ้าโฮสต์เป็นสมาชิก
- แก้ RLS ของ `realtime.messages`
  - **อ่าน (SELECT)** เปิดให้สมาชิกห้องเสมอ ลูกห้องจะได้ดูและซิงก์ต่อได้
  - **ส่ง (INSERT) แบบ presence** เปิดเสมอ รายชื่อสมาชิกจะได้ไม่หาย
  - **ส่ง (INSERT) แบบ broadcast** ผ่านได้เมื่อ *เป็นโฮสต์ของห้อง* หรือ *ยังไม่ถึง `guest_until`*
- โฮสต์จ่ายเงิน = เลื่อน `guest_until` ออกไป ไม่ต้องแก้โค้ดแอป
- ฝั่งแอปทำแค่ซ่อนปุ่มและอธิบายให้เข้าใจ ของจริงกันที่ฐานข้อมูล

## 3. แผนโฆษณา

- Google AdSense **แบนเนอร์ด้านล่าง** เท่านั้น
- **ห้ามซ้อนทับตัวเล่นวิดีโอ** และห้ามอยู่ในกรอบสเตจของจอกลาง
- **ห้ามคั่นระหว่างดู** ไม่มีโฆษณาก่อนเล่น ไม่มีโฆษณาแทรกกลางคิว
- ป๊อปอัปตอนเปิดเว็บครั้งแรกที่ปิดเอง — **ตัดทิ้ง** (เหตุผลในข้อ 5)
- หน้าไหนได้บ้าง
  - หน้าแรก — ได้ ปลอดภัยสุด ไม่มีตัวเล่น
  - หน้ารีโมทบนมือถือ — ได้ ไม่มีตัวเล่น และมีเนื้อหาของเราเอง (คิว อีโมจิ ปุ่มคีย์ ชื่อสมาชิก)
  - หน้าจอกลาง/โหมดดูด้วยกัน — **ไม่ใส่** เพราะมีตัวเล่นอยู่บนหน้าเดียวกัน
- ไม่แตะโฆษณาของ YouTube เลย ส่วนเสริมคาราโอเกะหยุดทำงานเองตอนโฆษณาเล่น (ทำแล้วใน commit `d282591`)

## 6. ความเสี่ยงใหญ่ที่สุด: ฟีเจอร์ปรับคีย์

กฎ YouTube เขียนไว้ตรง ๆ ว่าห้ามแยกหรือแก้ไของค์ประกอบเสียงของเนื้อหา YouTube ซึ่งการเปลี่ยนคีย์คือการแก้เสียง
แปลว่าฟีเจอร์คาราโอเกะของเราขัดกฎข้อนี้ ถึงแม้จะทำผ่านส่วนเสริมที่ผู้ใช้ติดตั้งเองก็ตาม

ทางเลือก

1. **ปล่อยไว้แบบนี้** ส่วนเสริมเป็นของผู้ใช้ ติดตั้งเอง เราไม่ได้แก้เสียงบนเซิร์ฟเวอร์ ความเสี่ยงคือถ้า YouTube ทักมา อาจต้องถอดฟีเจอร์ และห้ามเอาไปเป็นจุดขายของแพ็กเสียเงินโดยตรง
2. **ไม่เก็บเงินกับคีย์** ขายเฉพาะสิทธิ์ให้ลูกห้องส่งเข้าห้อง ส่วนคีย์เป็นของแถมฟรี ลดความเสี่ยงเรื่อง "หาเงินจากการแก้เสียงของ YouTube"
3. **ย้ายคาราโอเกะไปใช้ไฟล์เพลงของเราเอง** ผู้ใช้อัปโหลดไฟล์ แล้วเว็บเล่นเอง ปรับคีย์ได้ทุกอุปกรณ์รวมทีวี ไม่ต้องติดตั้งส่วนเสริม และไม่ติดกฎ YouTube เลย แลกกับค่าเก็บไฟล์และความรับผิดชอบเรื่องลิขสิทธิ์เพลงที่อัปโหลด

ข้อเสนอ: เอาข้อ 2 ตอนนี้ และวางข้อ 3 ไว้เป็นทางหนีทีไล่ ถ้าอยากโตเรื่องคาราโอเกะจริงจัง

## 7. แผนลงมือ (ยังไม่เริ่ม)

**เฟส 0 — วัดก่อนขาย**
- นับสถิติง่าย ๆ ว่ามีการเปิดห้องแต่ละโหมดกี่ครั้ง ลูกห้องเข้ากี่คน อยู่นานเท่าไร
- ยังฟรีทั้งหมด ไม่มีล็อกอิน
- เอาตัวเลขมาตัดสินว่าจะขายไหมและขายเท่าไร

**เฟส 1 — จำกัดเวลาลูกห้อง (ยังไม่เก็บเงิน)**
- เพิ่ม `guest_until` และแก้ RLS ตามข้อ 2
- หน้าจอบอกเวลาที่เหลือ และข้อความตอนหมดเวลา
- เปิดสิทธิ์ให้เองจากฐานข้อมูลสำหรับคนที่อยากลอง

**เฟส 2 — บัญชีและการจ่ายเงิน**
- ล็อกอิน Google สำหรับโฮสต์ (ลูกห้องยังไม่ต้องสมัคร)
- ตาราง `profiles` เก็บวันหมดอายุสมาชิก
- ช่องทางจ่าย เลือกระหว่าง Stripe (บัตร + พร้อมเพย์) หรือช่วงแรกโอนแล้วเราเปิดสิทธิ์ให้
- หน้าเสนอขายตอนหมดเวลา

**เฟส 3 — โฆษณา**
- AdSense แบนเนอร์หน้าแรกก่อน ดูรายได้จริง แล้วค่อยพิจารณาหน้ารีโมท
- ซ่อนโฆษณาให้สมาชิกที่จ่ายเงิน

1. เวลาฟรีต่อห้อง 30 นาที หรือมากกว่า

3. ราคาและรูปแบบ รายคืน รายเดือน หรือทั้งคู่
4. ช่องทางรับเงินช่วงแรก
5. เอาทางเลือกข้อไหนในเรื่องฟีเจอร์ปรับคีย์ (ข้อ 6)
