## 1. ตอนนี้เว็บทำอะไรได้

สี่โหมด โฮสต์สลับได้จากหัวห้อง เพื่อนในห้องเปลี่ยนตาม

| โหมด | จอโฮสต์ | คนอื่น |
| --- | --- | --- |
| ดูด้วยกัน | วิดีโอ + โน้ต ด้านบน, สมาชิก + คิว ด้านล่าง | มีตัวเล่นของตัวเอง เล่นตามโฮสต์ |
| รีโมท | จอกลาง วิดีโอใหญ่สุด มี QR ค้างไว้ (ย่อเก็บได้เมื่อคนเข้าครบ) | มือถือเป็นรีโมท เพิ่มคิว เล่น หยุด ข้าม |
| คาราโอเกะ จอกลาง | เหมือนรีโมท เพิ่มป้ายคีย์บนจอ | เพิ่มปุ่มคีย์ −/+ และรีเซ็ต |
| คาราโอเกะด้วยกัน | เหมือนดูด้วยกันแต่ไม่มีช่องโน้ต วิดีโอเต็มแถว คีย์อยู่ใต้ตัวเล่น | เหมือนกัน มีจอของตัวเอง คีย์ และปรับหน่วงเวลา สำหรับร้องกันคนละที่ (เนื้อเพลงอยู่ในวิดีโอคาราโอเกะอยู่แล้ว) |

คีย์ของสองโหมดคาราโอเกะต่างกันตรงแหล่งเสียง: จอกลางใช้เสียงจากเครื่องโฮสต์เครื่องเดียว จึงติดตั้งส่วนเสริมแค่เครื่องนั้น ส่วนคาราโอเกะด้วยกันทุกเครื่องเล่นเสียงเอง แต่ละเครื่องจึงต้องมีส่วนเสริมของตัวเองถึงจะได้ยินคีย์ใหม่ (เครื่องไหนไม่มีจะบอกไว้ใต้ปุ่มคีย์)

ของที่มีทุกโหมด

- **ครอสเฟด** เพลงใกล้จบเริ่มเพลงถัดไปแล้วเฟดทับกัน โฮสต์เลือก ปิด/3/6/10 วินาที กดข้ามเองเฟดสั้น 1.5 วินาที
- **ข้อความวิ่ง** ทุกคนพิมพ์ได้ วิ่งข้ามจอแบบสตรีมมิ่งจีน จอกลางวิ่งผ่านวิดีโอ โหมดดูด้วยกันวิ่งทั้งหน้าแต่เลี่ยงกรอบวิดีโอ โฮสต์ปิดได้
- **อีโมจิ** ทุกคนกดได้ แต่ละตัวมีจังหวะของตัวเอง เชียร์พุ่งเร็ว อบอุ่นลอยช้า กระจายสูงราว 30dvh ทุกคนเพิ่มอีโมจิของตัวเองได้คนละ 1 ตัว (เก็บในเครื่อง)
- **โน้ต/เนื้อเพลง** โฮสต์เปิดปิดได้ ปรับขนาดตัวอักษร A− A+ กดขยายอ่านเต็มจอ และเปิดให้เพื่อนช่วยเขียนได้
- **เข้าห้อง** สแกน QR ได้ในเว็บเลย ปุ่มอยู่ใต้ช่องรหัสห้องบนหน้าแรก ไม่ต้องออกไปเปิดแอปกล้อง (Chrome/Edge ใช้ตัวอ่านของเบราว์เซอร์ ที่เหลือโหลดตัวถอดรหัสเล็ก ๆ ตอนเปิดกล้อง) และช่องรหัสรับลิงก์เชิญเต็ม ๆ ได้ด้วย
- **ตั้งค่าห้อง** ปุ่มเดียวข้างคิว รวมทุกการตั้งค่าไว้ในกล่องเดียว (โฮสต์และหัวห้องร่วมเท่านั้น) — ครอสเฟด ข้อความวิ่ง โน้ต ใครปรับคีย์ได้ และ จำกัดคิวต่อคน (1/2/3/5/ไม่จำกัด), เลือกเพลงต่อไปแบบ ตามคิว/สุ่ม/โหวต, เกมระเบิดไมค์ (สุ่มคนมารับไมค์ ตั้งเวลาได้ 30 วิ – 2 นาที เพลงที่หาได้แทรกเป็นเพลงแรก หมดเวลาแล้วไม่ได้เพลงโดนหัก 1 คะแนน), เกมร้องเพลงมั่ว (เพลงที่เพิ่มถูกสุ่มให้คนอื่นร้อง) และให้คะแนน 1–5 ดาว มีคะแนนสดบนจอกลาง การ์ดสรุปตอนเพลงจบ และตารางคะแนนสะสมทั้งคืนแยกตามผู้ร้อง (ล้างได้จากกล่องตั้งค่า)
- **ส่วนเสริมเปลี่ยนคีย์** โหมดคาราโอเกะ จอกลาง เด้งหน้าตั้งค่าให้โฮสต์ทันทีที่เปิดห้อง ส่วนคาราโอเกะด้วยกันจะเด้งให้ "ทุกเครื่องที่ติดตั้งได้แต่ยังไม่ติดตั้ง" (คอม Chrome/Edge) ครั้งเดียว ส่วนมือถือกับทีวีขึ้นเป็นบรรทัดใต้ปุ่มคีย์แทนว่าเครื่องนี้ติดตั้งไม่ได้ จะได้ยินคีย์ต้นฉบับ
- **คู่มือ Discord** หน้า `/discord` (ลิงก์จากฟุตเตอร์หน้าแรก กล่องชวนเพื่อน และใต้แถบชดเชย) อธิบายสองวิธี: ไม่แชร์จอ (แนะนำ) กับโฮสต์แชร์จอ พร้อมวิธีตั้งชดเชยและปัญหาที่เจอบ่อย
- **ปรับหน่วงเวลา** (โหมดดูด้วยกันและคาราโอเกะด้วยกัน ฝั่งลูกห้อง) เลื่อนให้เครื่องตัวเองเล่นล่วงหน้า/ตามหลังโฮสต์ได้ ±5 วินาที สำหรับกรณีดูจอที่คนอื่นแชร์ใน Discord/Meet ค่าเก็บในเครื่องคนนั้น ไม่เข้าสถานะห้อง
- **คีย์** มีสองปุ่ม เพิ่มกับลด กดครั้งละ 1 หน่วย ซึ่งเท่ากับครึ่งเสียงจริง 0.5 (เลข +3 บนจอ = 1.5 ครึ่งเสียงที่ส่งให้ส่วนเสริม) โฮสต์เลือกได้ว่าใครปรับได้ (ทุกคน / คนที่ขอเพลงนั้น / โฮสต์เท่านั้น)

## 2. โครงสร้างโค้ด

```
app/
  room-client.tsx      ← หัวใจ: สถานะห้อง การกระจายข้อมูล การกู้ห้อง ตัวเล่น ข้อความ อีโมจิ
  page.tsx layout.tsx globals.css  ← หน้าเดียว ธีม KUMA ทั้งหมดอยู่ใน globals.css
  privacy/page.tsx     ← หน้านโยบายความเป็นส่วนตัว (ใช้กับหน้าร้านส่วนเสริม)
  api/video/route.ts   ← ดึงชื่อเพลงจาก YouTube oEmbed และกันคลิปที่ฝังไม่ได้
  components/
    home-screen.tsx    ← หน้าแรก
    watch-room.tsx tv-room.tsx remote-room.tsx  ← สามหน้าจอหลัก
    youtube-player.tsx ← ตัวเล่นสองเด็ค ครอสเฟด ส่งคีย์ให้ส่วนเสริม
    chat.tsx reactions.tsx key-helper.tsx queue.tsx room-panels.tsx ui.tsx
lib/
  room-state.ts        ← ชนิดข้อมูล ตัวลดสถานะ การกรองข้อมูลที่รับมาจากคนอื่น
  room-realtime.ts     ← ช่อง Supabase presence การต่อใหม่
  karaoke-key.ts       ← คุยกับส่วนเสริมเปลี่ยนคีย์
  youtube.ts supabase.ts
extension/             ← ส่วนเสริม KUMA Karaoke Key (ดูข้อ 4)
docs/                  ← เอกสารนี้ และร่างแผนหารายได้
```

หลักการที่ยึดไว้

- **โฮสต์เป็นเจ้าของความจริง** คนอื่นส่ง intent มา โฮสต์ตัดสินแล้วกระจายสถานะทั้งก้อนกลับไป พร้อม heartbeat
- **กรองทุกอย่างที่รับมา** `sanitize*` ใน `room-state.ts` เพราะใครก็ส่งข้อมูลเข้าห้องได้
- **สิทธิ์ตัดสินที่โฮสต์** เช่น ใครแก้โน้ตได้ ใครปรับคีย์ได้ ฝั่งหน้าเว็บแค่ซ่อนปุ่ม
- **ห้องอยู่แค่ตอนโฮสต์เปิดหน้า** ถ้าโฮสต์รีเฟรช เพื่อนในห้องส่งคิวกลับให้

## 3. คำสั่งที่ใช้บ่อย

```bash
npm run dev             # เปิด dev server
npm run build           # ตรวจว่า build ผ่านก่อน deploy
npm run lint
npx tsc --noEmit -p .
npm run extension:zip   # แพ็กส่วนเสริมเป็น public/kuma-karaoke-key.zip
```

Deploy คือ push ขึ้น `main` แล้ว Vercel ทำต่อเอง ไม่ต้องรัน migration และไม่ต้องเพิ่ม env ใหม่
ตัวแปรที่มีผลตอนนี้: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (หรือคู่ `SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`)
และ `NEXT_PUBLIC_KARAOKE_EXTENSION_URL` ซึ่งยังว่าง ใส่เมื่อส่วนเสริมขึ้นร้านค้าแล้ว

## 4. ส่วนเสริมเปลี่ยนคีย์

- โค้ดอยู่ใน `extension/` ใช้ Signalsmith Stretch (MIT) แปลงเสียงในหน้าวิดีโอ หน่วงราว 70 มิลลิวินาที
- คีย์ 0 ไม่แตะเสียง และตอนโฆษณา YouTube เล่นจะหยุดทำงานชั่วคราว
- ไฟล์สำหรับยื่นร้านค้าอยู่ใน `extension/store/` มีข้อความหน้าร้าน คำตอบเรื่องความเป็นส่วนตัว และภาพหน้าจอ 1280×800 สามรูป
- ตอนนี้แจกแบบโหลด zip แล้ว Load unpacked ซึ่งฟรีและใช้ได้เลย
- ทางเลือกถ้าอยากได้ปุ่มติดตั้งคลิกเดียว: Edge Add-ons ฟรีไม่มีค่าสมัคร หรือ Chrome Web Store เสีย 5 ดอลลาร์ครั้งเดียว ตั้งเป็นแบบไม่เผยแพร่สาธารณะได้ทั้งคู่
- ทีวีและมือถือติดตั้งส่วนเสริมไม่ได้ จอที่ให้เสียงต้องเป็นคอมที่ใช้ Chrome, Edge, Opera (Firefox มีขั้นตอนให้แต่ยังไม่ได้ทดสอบ) ถ้าไม่ใช่ ห้องยังใช้ได้ครบ แค่ปุ่มคีย์เปลี่ยนแต่ตัวเลข ซึ่งมีข้อความบอกไว้ในหน้าตั้งค่าที่เด้งตอนเปิดโหมดคาราโอเกะ

## 5. ทดสอบแล้วแค่ไหน

ทดสอบจริงด้วยเบราว์เซอร์อัตโนมัติ (Chrome for Testing ผ่าน Playwright)

- ส่วนเสริมเปลี่ยนคีย์: ป้อนเสียง 440Hz แล้ว +3 วัดได้ 521Hz, −2 ได้ 393Hz, +7 ได้ 662Hz ตรงตามทฤษฎี และทำงานกับ YouTube จริงภายใต้ CSP ของ YouTube
- ครอสเฟด: ทั้งแบบเพลงใกล้จบเองและแบบกดข้าม สลับเด็คถูกต้อง เสียงทับกันตามเวลาที่ตั้ง
- ข้อความวิ่ง อีโมจิ คีย์ 0.5 โน้ตเปิดปิด และหน้าตั้งค่าคาราโอเกะ ตรวจด้วยตาในเบราว์เซอร์
- `npm run build`, `npm run lint`, `tsc --noEmit` ผ่านทุกครั้งก่อน push

### ทดสอบบนเว็บจริงแล้ว (20 ก.ย. 2026)

เว็บจริงอยู่ที่ **https://watchtogether.kumadesign.dev** (Vercel deploy อัตโนมัติจาก `main`) ทดสอบด้วยหน้าโฮสต์ + หน้าลูกห้องขนาดมือถือพร้อมกัน

- ครอสเฟด: เฟดติดกันสามเพลงรวด เพลงใหม่เริ่มตอนเหลือประมาณเท่ากับค่าที่ตั้ง และยังเฟดปกติแม้ลูกห้องส่งอีโมจิกับข้อความรัว ๆ
- เกม & คิว (ตอนนี้อยู่ในกล่อง “ตั้งค่าห้อง”): ลิมิตคิวต่อคน, โหวตคิวต่อไป, ระเบิดไมค์ (สุ่มคน → เพลงที่หาได้แทรกหัวคิว → ตัวนับหยุด), ให้คะแนน, ร้องเพลงมั่ว ผ่านครบ 13 ข้อ
- ชดเชยดีเลย์จอแชร์: ตั้ง +2 วิ วัดได้ลูกห้องนำโฮสต์ 2.01 วิ, ตั้ง −1.5 วิ ได้ −1.49 วิ, กลับเป็น 0 แล้วตรงกันเหมือนเดิม และค่ายังอยู่หลังรีเฟรช
- ตรรกะห้อง (คิว โหวต คะแนน ระเบิดไมค์ การกรองข้อมูลจากสาย) ทดสอบแยก 23 เคส ผ่านหมด

**ข้อควรรู้เวลาทดสอบเอง** ถ้าเปิดหน้าโฮสต์กับหน้าลูกห้องในเบราว์เซอร์โปรไฟล์เดียวกัน ทั้งสองแท็บจะได้ผู้ใช้นิรนามของ Supabase คนเดียวกัน ต่างฝ่ายต่างคิดว่าตัวเองเป็นโฮสต์และไม่เห็นกัน ต้องใช้คนละโปรไฟล์ (หรือคนละเครื่อง) เสมอ

**ยังไม่ได้ทดสอบ**

- คนจริงหลายเครื่องพร้อมกันในปาร์ตี้จริง (ที่ทดสอบคือเบราว์เซอร์อัตโนมัติสองโปรไฟล์)
- ส่วนเสริมบน Chrome และ Edge ตัวจริงของผู้ใช้ (ทดสอบบน Chrome for Testing เท่านั้น)
- ยังไม่มีชุดทดสอบอัตโนมัติใน repo (สคริปต์ที่ใช้เป็นสคริปต์ชั่วคราวนอก repo)

## 6. ความเสี่ยงที่ควรรู้

- **นโยบาย YouTube** ห้ามแยกหรือแก้ไขเสียงของเนื้อหา YouTube ซึ่งการเปลี่ยนคีย์เข้าข่าย ข้อเสนอคืออย่าเอาฟีเจอร์นี้ไปเป็นจุดขายของแพ็กเสียเงิน รายละเอียดอยู่ใน `docs/monetization-plan.md`
- **แผ่นใสคลุมตัวเล่น** ฝั่งลูกห้องในโหมดดูด้วยกันมี div ใสคลุมไว้กันกดสลับ เข้าข่าย "บล็อกการทำงานของตัวเล่น" ควรเปลี่ยนไปใช้พารามิเตอร์ของตัวเล่นแทน
- **ข้อความและอีโมจิบนจอกลาง** วิ่งผ่านวิดีโอ อาจบังโลโก้หรือชื่อวิดีโอ ถ้าอยากปลอดภัยกว่านี้ให้วิ่งเฉพาะนอกกรอบวิดีโอเหมือนโหมดดูด้วยกัน
- **ความปลอดภัยของห้อง** ใครที่มีลิงก์ห้องส่งข้อมูลปลอมเข้ามาได้ ข้อมูลถูกกรองแล้วแต่ยังแกล้งกันได้ในระดับกวนประสาท
- **รหัสห้องยังขึ้นต้นด้วย WAVE-** เพราะฐานข้อมูลบังคับรูปแบบนี้ เปลี่ยนเมื่อไรต้องมี migration และรันใน Supabase ก่อน deploy

## 7. งานที่ค้างและข้อเสนอลำดับถัดไป

1. ลองกับคนจริงในปาร์ตี้จริงสักรอบ (เบราว์เซอร์อัตโนมัติผ่านหมดแล้ว ดูหัวข้อ 5)
2. ตัดสินใจเรื่องช่องทางแจกส่วนเสริม: อยู่แบบ zip ต่อ หรือขึ้น Edge Add-ons แบบไม่เผยแพร่สาธารณะ (ฟรี)
3. ตัดสินใจเรื่องหารายได้ ร่างและตารางเทียบกฎอยู่ใน `docs/monetization-plan.md` ยังค้างคำถาม 5 ข้อท้ายไฟล์
